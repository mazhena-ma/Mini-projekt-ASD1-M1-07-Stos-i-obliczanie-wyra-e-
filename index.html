    02 / Porównaj, nie zgaduj

    n = liczba tokenów wejścia (z nawiasami). P = push, Z = pop, O = peek, H = maksymalna liczba elementów. Liczniki dotyczą tylko stosu badanego algorytmu. Odczyt wizualizacji i walidator nie są wliczane. Wyniki pierwszych dwóch wyrażeń nie są równoważne.

    Wyrażenie / nONP / wynikKonwersja P/Z/O/HObliczanie P/Z/O/H

    Algorytmy: O(n) czasu i O(n) pamięci pomocniczej; push/pop/peek: O(1) w modelu dostępu indeksowego. Walidacja: O(m+n), gdzie m to długość tekstu. Kopiowane klatki i pozostałe fragmenty tekstu: do O(n² + n·m) pamięci/czasu (dla kontrolera O(m²)). Animacja i historia są kosztem interfejsu, a nie dowodem złożoności stosu.

    03 / Przewidź następny krok

    Który zdjęty operand jest lewą stroną odejmowania?

    Drugi. Najpierw zdejmujemy prawy b, potem lewy a; liczymy a − b. Dla stosu [2, 7] otrzymamy 2 − 7 = −5.

    Dlaczego 8 / 2 / 2 daje 2, a nie 8?

    Dzielenie jest lewostronne. Przy drugim / zdejmujemy wcześniejsze / o równym priorytecie. ONP: 8 2 / 2 /, czyli (8 / 2) / 2.

    04 / Testy automatyczne

    Test / wejścieOczekiwaneUzyskaneStatus

    Cel i ograniczenia

    Stos LIFO przydaje się do cofania operacji i obsługi zagnieżdżeń. Kontroler sprawdza wyłącznie strukturę (), [] i {}, ignorując pozostałe znaki — nie sprawdza składni programu. Konwersja stosowa usuwa potrzebę nawiasów w ONP i służy parserom. Ewaluator oblicza ONP bez eval, ale nie jest kalkulatorem symbolicznym.

    Kalkulator: 0–99, + − * /, (), maksymalnie 60 tokenów, bez funkcji i operatorów jednoargumentowych. Wyniki pośrednie mogą być ujemne/ułamkowe. JavaScript Number może zaokrąglać. Pozycje od 0 (indeksy UTF-16). Limit pola 500 znaków chroni wizualizację. Zmiana danych rozpoczyna nowy przebieg.
